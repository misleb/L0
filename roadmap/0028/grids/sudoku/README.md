# sudoku

Solves 9 by 9 Sudoku by backtracking with constraint checks.

```
tools/l0 build sudoku.l0 main.l0 -o sudoku
./sudoku FILE [undo|copy]        FILE of - reads standard input
```

One puzzle per line, 81 cells, `0` or `.` empty; blank lines skipped. One
output line per puzzle: the 81-digit solution, `no solution`, or
`invalid: ...`. Exit status 1 if any line was invalid.

The search takes the empty cell with the fewest candidates (the first on a
tie, stopping early at 0 or 1) and tries digits in increasing order. State
is a `data` value of four arrays: the board, and flags per row, column, and
box (element `unit * 10 + d` is 1 when the unit has d).

- `undo` (default): the state is handed down and back up in the `Outcome`,
  and a failed digit is taken out again. Every update in place.
- `copy`: keeps the state it had and lets `array_set` copy it on each
  placement, the natural way with values. 4 copies (351 words) per node.

## Status

Works. `tools/l0 test sudoku.l0 sudoku_test.l0`: 11 tests pass under
`L0_RC_CHECK` (the Wikipedia puzzle both ways, parse errors, conflicting
givens, a consistent but unsolvable puzzle, the empty board, `solve_all`
over an in-memory file, and a property test on 40 random puzzles that both
modes agree and give a valid solution keeping the givens). Both modes match
`sudoku.py` on all 99 hard puzzles.

## Measurements

`hard.txt`: 7 well-known hard puzzles (Inkala's, top95's first five, Easter
Monster) and 92 minimal puzzles generated by `sudoku.py make 92 1`. 225,578
search nodes in all, identical in L0 and Python.

| run | time | peak RSS | array copies | sets in place |
| --- | --- | --- | --- | --- |
| L0 undo | 0.29 s | 1.6 MB | 0 | 1,799,471 |
| L0 copy | 0.32 s | 1.8 MB | 902,312 (79M words) | 17,471 |
| L0 undo, candidate check inlined | 0.16 s | | 0 | |
| Python 3.14, same algorithm | 3.08 s | 15.5 MB | | |

Copying the whole state per node costs only 10%. What does cost: a third of
all samples are `l0_dec`, from passing the three flag arrays to the helper
`free` that only reads them; writing its lookups inline in `candidates`
takes 0.29 s to 0.16 s (`../probes/borrow/`, `../limits/02`).

The first run of a freshly built binary took 1.3 s rather than 0.3 s
(macOS checking the new executable); every number here is a warm run.
Build: 0.40 s. Tests: 1.5 s.

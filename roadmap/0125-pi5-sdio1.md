# 0125: the Raspberry Pi 5's SD host controller, sdio1, is a region, with its interrupt

Kind: language
Status: done, changelog "The Raspberry Pi 5's SD host controller, sdio1,
is a region, with its interrupt"; no run on a board
Needs: 0122

## Why

L0S's `probes/storage/REQUEST-pi5-sdio.md`. Its `sdhci` driver already
brings SD cards up on QEMU through `sdhci-pci`; on the Pi 5 the microSD
slot is behind the BCM2712's own SDHCI, `sdio1`, and `open_device`
refuses it, since section 10.3 lists no SD controller. L0S's
`probes/storage/want.l0` opens it and gets `DeviceFailed`; L0S's roadmap
0004 (a disk on the Pi 5) is blocked on it.

## The plan

- spec 10.3: the Pi's region table gains `sdio1`, 0x1000FFF000, 0x600,
  its SDHCI registers and the brcmstb cfg block in one run; its interrupt
  table gains 305, the GIC's SPI 273
- `runtime/board/pi5-aarch64.ll`: the device, in block 64, and 305 in
  `l0_board_irq_exists`
- `tests/virt/pi5/sdio`: opens it, ranges beside it that are none, and
  enables 305 and the numbers either side
- no emulator: checked by building and linking; a first run is the user's

## Done when

- the checklist in the `l0-bootstrap` skill
- the pi5 target builds; `tools/test.sh --virt` green

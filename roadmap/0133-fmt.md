# 0133: l0 fmt, the closers from the indentation

Kind: tooling
Status: done
Needs: 0132

## Why

Miscounted closing parens are the most common way an agent wastes time
writing L0: "the cause of every parse error hit while writing the
compiler" (the l0-code skill), with runs of up to 19 closers ending lines
of the compiler and the kernel. Counting a run of identical tokens against
context lines away is what a model does worst; judging that one line is
indented under its parent is what it does well. So the tool supplies the
closers from the indentation, as Parinfer's indent mode does, and the
agent's layout becomes the specification.

The program that could not be written before 0132 made the tool itself an
instance: `tools/fmt.l0`'s state is a six-field record read and replaced
by name.

## Done when

- `tools/fmt.l0` writes a source back with each line's trailing closers
  supplied from the next line of code's indentation, nothing else changed
- `tools/build.sh` builds it, `tools/install.sh` installs it, and `tools/l0
  fmt FILE...` rewrites in place while `l0 fmt --check FILE...` only says
  what would change
- `tests/unit/fmt_test.l0` covers the cases; `tests/io/fmt` runs the tool
  over every `.l0` under `compiler/`, `lib/`, and `tests/virt/user/`, which
  come back byte-identical
- the skills say to run `l0 fmt` before `l0 check`
